# プロジェクト構造

## 構成方針

ドメイン（ハードウェア / ファームウェア / ドキュメント）でトップレベルを分け、
その下は **機種単位** のサブディレクトリで区切る。機種名はターゲットとなる製品や用途に由来する。

```
hardware/<機種名>/          例: hardware/daiso-clock/
firmware/<プロジェクト名>/   （未着手）
docs/                       設計資料
```

## ディレクトリのパターン

### KiCad プロジェクト
**場所**: `hardware/<機種名>/`
**用途**: 1 機種につき 1 KiCad プロジェクト。回路図・基板・ローカルライブラリ・製造データを同居させる
**例**: `hardware/daiso-clock/mizuyari01.kicad_pro`

ファイル名はプロジェクト名（`mizuyari01`）に揃え、ディレクトリ名とは独立させてよい。
ディレクトリ名は「何を相手にするか」（`daiso-clock`）、ファイル名は「何号機か」（`mizuyari01`）を表す。

### サブ回路・部分検証
**場所**: `hardware/<機種名>/<ブロック名>/`
**用途**: 負荷や周辺ブロックを単独で検証するための小規模 KiCad プロジェクト
**例**: `hardware/daiso-clock/motor/` — モータ駆動段だけを切り出して過渡解析する

本体プロジェクトに階層シートとして取り込むのではなく、独立プロジェクトとして分離する。
検証が済んだ結果だけを本体の回路図に反映する。

### ファームウェア
**場所**: `firmware/<プロジェクト名>/`
**用途**: マイコン側の実装。開発環境が確定してから作成する

## 命名規則

- **ディレクトリ**: kebab-case（`daiso-clock`）
- **KiCad ファイル**: プロジェクト名 + 標準拡張子。プロジェクト内で名前を統一する
- **ローカルシンボルライブラリ**: 部品名そのまま（`NE555.lib`）
- **グローバルラベル**: 機能を表す短い名前。信号は大文字（`ALM`, `MTR-N`）、内部ノードは小文字可（`tmout`）
- **リファレンス指定子**: KiCad 標準（`R1`, `C4`, `Q2`, `U1`, `J1`, `RV1`, `H1`）

## バージョン管理の方針

KiCad ファイルは S-expression テキストなので、通常どおり Git で差分管理する。

**コミットする**:
- `.kicad_pro` / `.kicad_sch` / `.kicad_pcb`（設計の実体）
- プロジェクトローカルのシンボル・フットプリントライブラリ
- シミュレーション設定（解析条件の再現に必要）

**コミットしない**:
- バックアップと自動保存（`*.bak`, `*-backups/`, `_autosave-*`）
- キャッシュ（`fp-info-cache`, `*-cache.lib`）
- ユーザ固有の表示状態（`.kicad_prl`）
- 圧縮済みの提出用アーカイブ（`*.zip`）

**リビジョンはファイルのコピーで残さない**:
設計の履歴は Git のコミットとタグで表す。`<name>-1.kicad_sch` のような連番コピーを
プロジェクト内に置くと、`.kicad_pro` から参照されない孤立ファイルになり、
どれが最新かが判別できなくなる。

**製造データ（ガーバー・ドリル）**:
発注した版のみを残す。`docs/` または機種ディレクトリ直下に発注日・リビジョンが分かる形で置き、
日常の編集ごとには再生成しない。

## 設計上の原則

- **1 機種 1 プロジェクト**: 機種が変われば回路を共有せず、ディレクトリを分ける
- **検証用と実装用を分けない**: シミュレーション素子は実回路と同一シートに置き、条件を見失わないようにする
- **外部インタフェースは端子台かワイヤコネクタに集約**: 基板外への配線は必ずコネクタ部品を経由させ、直接はんだ付けを前提にしない
