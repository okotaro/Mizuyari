# 技術スタック

## アーキテクチャ

ハードウェア（回路）とファームウェアを分離したモノレポ構成。
現行の `daiso-clock` 機種はアナログ回路のみで完結しており、ファームウェアは未着手。

信号の流れは次の一方向:

```
時計アラーム出力 (ALM)
  → 入力受け (Q3 / 2SC1815)
  → タイマ (U1 / NE555P + RV1 + C)   ← 給水時間を決定
  → ゲート駆動 (Q2 / N-ch MOSFET, TO-251)
  → 負荷 (モータ・ポンプ, MTR-N)     ← D1 還流ショットキーで保護
```

電源は時計側（3V 系, `V_WATCH`）と駆動側（6V 系）を分けて扱う。

## コア技術

- **回路CAD**: KiCad 10.0（`version 20260306` 系フォーマット、`generator_version "10.0"`）
- **回路シミュレーション**: KiCad 内蔵 ngspice。過渡解析（`.tran`）を前提とする
- **基板**: 2 層、板厚 1.6mm、外形 75 x 50mm、表面処理なし
- **実装方式**: スルーホール（THT）中心。MOSFET のみ TO-251 を使用
- **ファームウェア**: 未確定（PlatformIO / ESP-IDF / STM32Cube のいずれも未採用）

## 主要部品

汎用品のみで構成し、入手性を優先する。

- **U1 NE555P**（DIP-8）: 給水時間の生成。互換のシンボル定義を `NE555.lib` にローカル同梱
- **Q3 2SC1815**（TO-92）: アラーム信号の受け・レベル変換
- **Q2 N-ch MOSFET**（TO-251）: 負荷スイッチ。型番は未確定（シンボルは汎用 `Q_NMOS_GDS`）。検討過程では 2SK4017（TO-220）を割り当てた版があり、現行はパッケージが TO-251 に変わっている
- **D1 ショットキー**（DO-41）: 誘導性負荷の還流
- **RV1 10k 半固定**（Piher PT-6-V）: 給水時間の現場調整
- **C4 470u / C2・C3 0.1u**: 電源平滑とデカップリング
- **J1 / J2 ターミナルブロック（MX126-5.0, P5.00mm）, J3 3 極はんだ付けワイヤ**: 外部配線

## 設計標準

### シンボルとフットプリント
- シンボルは KiCad 標準ライブラリを優先する。標準にないものだけをプロジェクトローカルに置く（例: `NE555.lib`）
- 新規部品は必ずフットプリントを割り当てる。THT を既定とし、混在させない
- ピン番号の対応（例: `1=G 2=D 3=S`）は回路図上に注記を残す

### シミュレーション
- 実部品記号と並行して `Simulation_SPICE:*` の電源・素子を配置し、同一シートで過渡解析できる状態を保つ
- 電源条件は実機の電圧（3V / 6V）に合わせる
- シミュレーション設定はプロジェクトに同梱し、解析条件を再現できるようにする

### ネット命名
- 機能が明確な信号にはグローバルラベルを付ける（`ALM`, `tmout`, `MTR-N`）
- 電源ネットは系統ごとに分ける（`VCC`, `V_WATCH`, `GND`）
- 電源投入元には `PWR_FLAG` を付け、ERC の電源未駆動エラーを出さない

### 検証
- 回路図変更後は ERC、基板変更後は DRC を通す
- 製造データ（ガーバー・ドリル）は基板確定後にのみ再生成し、単発の編集のたびに更新しない

## 開発環境

### 必要なツール
- KiCad 10.0 以降（eeschema / pcbnew / ngspice）
- Git（バイナリではなく S-expression テキストとして差分を取る）

### よく使う操作
```bash
# 回路図・基板を開く
kicad hardware/<project>/<project>.kicad_pro

# 変更点の確認（KiCad ファイルはテキスト形式なので diff 可能）
git diff -- hardware/
```

## 主要な技術判断

- **アナログ完結を先行させる**: マイコンなしで要件を満たせるか先に確認し、ファームウェアの採用可否は後段で判断する
- **時計を改造しない**: アラーム出力を借用するだけに留め、時計本体の分解・改造範囲を最小化する
- **駆動段を 2 段に分ける**: 555 の出力で直接負荷を駆動せず、MOSFET を挟んで電流とノイズを分離する
- **THT 中心**: 手はんだでの試作・修正のしやすさを優先する
